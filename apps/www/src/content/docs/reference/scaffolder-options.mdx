`create-nimbus-docs` sets up a project with layouts, components, content schemas, search, a sitemap, share cards, and a Markdown version of every page. For a guided first run, follow the [Quickstart](/start-here/quickstart); this page lists every option.

## Requirements

- **Node** 22.12 or later
- **A package manager** — npm, pnpm, yarn, or bun
- **Git** — for last-updated dates, which come from commit history

## Scaffold

<PackageManagers type="create" pkg="@cloudflare/nimbus-docs@latest" />

The scaffolder asks:

<Steps>
  <Step title="Directory">
    Where to create the project; press Enter for `my-docs`. Pass it as the first argument, such as `my-docs`, or `.` for the current folder. The folder must be new, empty, or hold only `.git`, such as a freshly cloned repository.
  </Step>
  <Step title="Starter content">
    **Getting started guide + example pages**, or **Empty**, just the shell for your own content. Flag: `--content starter|empty`.
  </Step>
  <Step title="Package manager">
    npm, pnpm, yarn, or bun; the default is the one that runs the scaffolder. It installs dependencies with your choice unless you pass `--skip-install`. Flag: `--package-manager <pm>`.
  </Step>
  <Step title="Git">
    Whether to initialize a repository and make a first commit. Inside an existing repository it does neither. Flag: `--git` or `--no-git`.
  </Step>
  <Step title="Output mode">
    **Static** prerenders every content collection route and deploys anywhere. **Server** renders docs pages on request. You can override individual collections later. Flag: `--deploy` chooses static, `--adapter` chooses server.
  </Step>
  <Step title="Deploy target or adapter">
    Static output asks for a deploy target: Cloudflare or another static host (flag: `--deploy cloudflare|other`). Server output offers Cloudflare; the `--adapter` flag also accepts `vercel`, `netlify`, and `node`.
  </Step>
</Steps>

Pass `--yes` to accept every default without prompts. Without a terminal, such as in CI or when an agent runs it, pass `--yes` or a flag for every question; otherwise the scaffolder exits with the list of unanswered questions and their flags. Unknown flags, and flags that contradict each other, stop the scaffolder before it writes anything. Pass `--help` to list every flag.

If installing dependencies fails, the scaffolder keeps the project, prints the commands that finish the setup, and exits with status 1. To scaffold from a local template directory instead of downloading one, such as when working on templates offline, pass `--template-dir <path>`.

With npm, put `--` before the arguments, or npm keeps the flags for itself:

```sh
npm create @cloudflare/nimbus-docs@latest -- my-docs --yes
```

<Aside>
  Yarn 4 skips package versions published less than a day ago, so on a release day `yarn dlx` runs the previous scaffolder. Wait a day, use another package manager, or set `YARN_NPM_MINIMAL_AGE_GATE=0` for that run.
</Aside>

## What lands in your repo

<FileTree>
- my-docs/
  - src/
    - components/
      - ui/
    - content/
      - docs/
    - pages/
    - styles/
      - globals.css
    - components.ts
  - AGENT.md
  - CLAUDE.md
  - astro.config.ts
  - nimbus.json
  - package.json
  - pnpm-workspace.yaml
  - wrangler.jsonc
</FileTree>

`AGENT.md` is the guide for coding agents working in the project, and `CLAUDE.md` points to it. `nimbus.json` records the last Nimbus version whose upgrade steps the site has reviewed; keep it committed. `pnpm-workspace.yaml` ships only with pnpm, for its dependency build-script settings, and Yarn sites get `.yarnrc.yml` instead. `wrangler.jsonc` ships only when you deploy to Cloudflare.

The `nimbus-docs` npm package ships the invisible plumbing (integration, data helpers, schemas). Everything visible — components under `src/components/`, MDX content under `src/content/docs/`, routes under `src/pages/`, design tokens in `src/styles/globals.css`, and the MDX globals registry at `src/components.ts` — copies into your repo and is yours to edit.

To run, build and publish the site, see the [Quickstart](/start-here/quickstart) and [Deploy](/publish/deploy).
