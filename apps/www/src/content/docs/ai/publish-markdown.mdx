Add the five endpoints that serve alternate Markdown/MDX versions, site and section `llms.txt` indexes, and `llms-full.txt`. The Nimbus integration must already be present in `astro.config.ts`.

## 1. Add alternate page versions

Create the clean Markdown version:

```ts title="src/pages/[...slug]/index.md.ts"
import { markdownRoute } from "@cloudflare/nimbus-docs/agent-endpoints";

export const prerender = true;
export const { GET, getStaticPaths } = markdownRoute();
```

Create the MDX source version:

```ts title="src/pages/[...slug]/index.mdx.ts"
import { markdownSourceRoute } from "@cloudflare/nimbus-docs/agent-endpoints";

export const prerender = true;
export const { GET, getStaticPaths } = markdownSourceRoute();
```

These two routes serve every collection, including docs versions, a blog at `/blog`, and API references. API pages have a `.md` version but no `.mdx` source. Pages in hidden versions have neither. Collections you add later need no new route files. To customize the output for some or all pages, see [Override a default](/ai/override-markdown).

The `prerender = true` lines are the static default. With a [`rendering` policy](/configuration#rendering), a page's Markdown follows its collection's rendering mode automatically: a request-rendered collection serves its Markdown and MDX versions on request from these same routes, and prerendered collections keep their static files.

## 2. Add the site index

Create the site-wide discovery index:

```ts title="src/pages/llms.txt.ts"
import { llmsRoute } from "@cloudflare/nimbus-docs/agent-endpoints";

export const prerender = true;
export const { GET } = llmsRoute();
```

## 3. Add llms-full.txt

Create the file containing all discoverable documentation:

```ts title="src/pages/llms-full.txt.ts"
import { llmsFullRoute } from "@cloudflare/nimbus-docs/agent-endpoints";

export const prerender = true;
export const { GET } = llmsFullRoute();
```

This file is optional. Without it, Nimbus doesn't build `llms-full.txt` and `llms.txt` doesn't link to it.

When the document would be over 25 MiB (Cloudflare's per-file limit), `/llms-full.txt` becomes an index of one `llms-full.txt` per section, such as `/reference/llms-full.txt`. Nimbus serves those files from a route of its own, beside this one, so there's nothing to add. Wrapping this route's `GET` doesn't change the section files.

- A section under the limit holds its pages in full, as `llms-full.txt` does. The index gives its size.
- A section over the limit is itself an index: it links its sub-folders' files, marked "split further" where they're split again, and links each of its own pages' Markdown. A folder over the limit with no sub-folders is a list of links to its pages.
- Pages at the top of the site are linked from `/llms-full.txt`, not included in it.

The build log lists the files it wrote. On Cloudflare (the adapter, or a `wrangler` file), the build warns about any agent file over 25 MiB, including a single page's Markdown, because that file would fail the deploy.

## 4. Add section indexes

Create the route for paths such as `/writing/llms.txt` and `/reference/functions/llms.txt`:

```ts title="src/pages/[...section]/llms.txt.ts"
import { llmsSectionRoute } from "@cloudflare/nimbus-docs/agent-endpoints";

export const prerender = true;
export const { GET, getStaticPaths } = llmsSectionRoute();
```

Each section index lists the pages directly in its folder, then links each sub-folder's own `llms.txt` under "Sections", so an agent descends one level at a time. A folder with even one page gets its own index; a folder holding only an `index.mdx` is a page of its parent. A section is named by its index page's `sidebar.group.label`, then its title, then the folder name. A route in a `[section]` folder (from an older starter) still works: it serves one index per top-level section listing every page under it. Rename the folder to `[...section]` to get the nested indexes.

Each `GET` returns `404` for an unknown section. Rendered on request, it returns a `500` without details when an index can't be read, and logs the error. To change what a route serves, see [Override a default](/ai/override-markdown#override-an-llmstxt-index).

The `llms.txt` endpoints follow the rendering policy the same way: the site index and `llms-full.txt` render in `rendering.default`, and a section index renders in the mode of the collection it lists. The `agent-endpoints` helpers support either mode and require the Nimbus Astro integration. The build still warns about a Markdown version or `llms.txt` index in a prerendered collection that no route generated, and names the route that serves it.

## Verify

Run a production build, then start Astro's production preview:

```sh
pnpm build
pnpm preview
```

In another terminal, replace `get-started` and `writing` with routes that exist in the project. If Astro has a deployment base, prefix each path with it:

```sh
curl --fail http://localhost:4321/get-started/index.md
curl --fail http://localhost:4321/get-started/index.mdx
curl --fail http://localhost:4321/llms.txt
curl --fail http://localhost:4321/llms-full.txt
curl --fail http://localhost:4321/writing/llms.txt
```

Each command must return content with a successful status. A `404` means the corresponding route file is missing, or the collection isn't a page collection — only collections made with Nimbus's helpers publish Markdown; wrap a custom loader with `withNimbusMarkdown()` as described in [Other collections](/writing/pages-and-routing#other-collections). If a section index is absent, confirm that the section has discoverable pages and appears in `/llms.txt`.

## Direct rendering

`renderEntryAsMarkdown()` and `getEntryMarkdown()` remain available for entry bodies that do not contain `<Render>`. Passing a body with `<Render>` throws. Use the endpoints above for alternate authored Markdown versions and `llms.txt` indexes. `getEntryMarkdown()` also loads API citation data and is intended for prerendered routes.
