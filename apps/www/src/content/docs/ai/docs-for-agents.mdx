Nimbus serves documentation through endpoints that AI tools can read without parsing the HTML site.

## What ships

- **Alternate Markdown/MDX versions for every discoverable page** — `/<slug>/index.md` contains clean Markdown with components converted to text, while `/<slug>/index.mdx` retains imports, JSX, and directives. Nimbus resolves links and reusable snippets during the build. The `.md` version links to its `.mdx` source. API reference pages have only the `.md` version. Hidden versions do not emit either file.
- **A site `llms.txt` index** — names top-level pages and section indexes of the current docs. Each section index links its discoverable pages to their alternate Markdown versions. Older docs versions aren't listed; each has its own index at `/<version>/llms.txt`.
- **`llms-full.txt`** — combines discoverable pages into one Markdown document, excluding non-current prose versions. AI tools and indexing systems can fetch the current site in one request. Nimbus generates it during the build so rebuilds are byte-identical.
- **Per-section indexes at `/<section>/llms.txt`** — each top-level group and collection (e.g. a `blog` or a docs version) gets its own index.
- **Version labels** — on versioned sites, every alternate Markdown version's frontmatter carries a `version:` key (resolved from your `versions` manifest) so agents can pin a version. Unversioned sites emit nothing.
- **JSON-LD in every page head** — structured data so search and agent tools recognize what they're looking at.
- **`/robots.txt` and a sitemap** — wired automatically when `site` is set.

```text title="/llms.txt"
# Nimbus

A way to build documentation sites on top of Astro.

## Pages
- [Get started](https://nimbus-docs.com/get-started/index.md)
- [Installation](https://nimbus-docs.com/installation/index.md)
```

## Agent discovery

Nimbus generates `/.well-known/ard.json` and the compatible `/.well-known/ai-catalog.json` from the site's published capabilities. The files have identical content, validated against the pinned ARD v0.91 and AI Catalog 1.0 schemas. A default docs site advertises its `llms.txt` index and homepage Markdown; homepage headers also link to visible API documentation. Removing the `llms.txt` route also removes its discovery entry. If no discoverable resources remain, the manifest has an empty `entries` array. This is valid against the pinned schemas, but does not satisfy checkers that require at least one entry.

If your site already owns either discovery path in `publicDir` or `src/pages`, Nimbus stops the build rather than overwriting it. Preserve any custom entries before moving the owner file or route; sites sharing an origin should combine entries in the origin deployment configuration.

The homepage Markdown at `/index.md` uses your published root content entry when one exists. Otherwise, it reuses the bytes from `/llms.txt`. A root entry with `noindex: true` remains directly readable but is omitted from discovery.

Homepage responses include HTTP `Link` headers pointing to discovery, the index, and the Markdown alternate. Nimbus emits `_headers` on every static build, even without a detected deployment target, so discovery works when the output is later uploaded to a compatible host. Request-rendered homepages receive the same links through middleware. Owner-written `_headers` rules and existing response links are preserved. Each generated link has its own `Link:` line to avoid overflowing Cloudflare's [2,000-character line limit](https://developers.cloudflare.com/workers/static-assets/headers/). Cloudflare comma-joins duplicate values, preserving owner links alongside Nimbus's links. Hosts that do not support `_headers` need equivalent response-header configuration.

### Sites under a base path

With Astro `base: "/docs"`, documentation links include `/docs`, but well-known discovery URLs remain at the origin root. The Cloudflare adapter handles this mounting automatically for server output. For other hosts, deploy the emitted `.well-known` directory at `https://your-domain/.well-known/`, alongside the site's mounted output, and apply its `_headers` rules there. If another site owns that origin's discovery document, combine the entries in the origin's deployment configuration. Local development serves these origin-root discovery URLs automatically.

With `output: "static"`, `base`, and `@astrojs/cloudflare` 14.3.3 together, the adapter generates a Wrangler configuration pointing inside the base directory. Set the outer asset root explicitly with [Wrangler's `--assets` option](https://developers.cloudflare.com/workers/wrangler/commands/workers/):

```sh
pnpm exec wrangler dev --assets ./dist/client
pnpm exec wrangler deploy --assets ./dist/client
```

These paths assume Astro's default output directories. Adjust them if you customize the build output. This workaround is specific to static output with the Cloudflare adapter and a base path; the default static starter does not install that adapter.

### Content Signals

New starters include an editable `Content-Signal` declaration in `src/pages/robots.txt.ts`, allowing search, AI input, and AI training. Review those choices before publishing and change each value to `no` where appropriate. Existing projects keep their current robots route; Nimbus provides optional upgrade guidance instead of replacing it.

Content Signals describe permitted uses. `robots.txt` directives are requests to crawlers, not access protection. Neither restricts access or replaces authentication. Keep private material outside publicly served collections and assets. See the [Content Signals policy](https://contentsignals.org/) for the meaning of each directive.

## How pages are indexed

Indexing is multi-collection by default and schema-tolerant — every prepared collection registered in `src/content.config.ts` (except `partials` and reserved names) is walked, reading `title` and `description` when present. There is no per-page opt-in; all discoverable pages are listed. Hidden versions are excluded, and `/llms-full.txt` omits non-current prose versions.

Alternate Markdown/MDX versions and `llms.txt` indexes use public agent-endpoint assets. Request-time authorization cannot make private material safe here. Keep private material outside public content collections. Nimbus omits excluded entries and fails the build when it cannot determine whether content is public.

To keep a page **out** of the `llms.txt` indexes, set `draft: true` (excluded entirely) or `noindex: true`. A page that should never be agent-readable belongs outside the content collection altogether.

### Custom content loaders

Nimbus's collection factories prepare Markdown automatically. If a custom loader retains Markdown bodies for alternate Markdown versions or `llms-full.txt`, wrap it with `withNimbusMarkdown()` from `@cloudflare/nimbus-docs/content`. See [Other collections](/writing/pages-and-routing#other-collections) for a complete example.

## Route setup

New projects include these routes. To add or update them in an existing project, follow [Markdown and llms.txt endpoints](/ai/publish-markdown).

## AGENT.md

The scaffolder writes an `AGENT.md` at the project root — the same context a coding agent reads when working in your repo. It's a real file you maintain; keep it in sync with your project's conventions.

## Why it matters

The cost of being a dead end on the agent web is real and growing. Because these files and metadata are defaults, a Nimbus site is legible to agents the day it ships — see [Metadata and SEO](/ai/metadata-and-seo) for the human-search side.
